## What I did today

- Audited overnight orchestrator run: `backfill_risk_free`,
  `backfill_underlying`, `backfill_news`, and `score_sentiment` all
  reached `complete 28/28` with zero errors. Sentiment files split
  correctly: 21 train + 5 validation + 2 holdout parquets.
- Fixed `UnicodeEncodeError` in `python -m src.orchestrator status` on
  Windows: the cp1252 default console couldn't encode the `→`
  arrows in the `match_events` stub note. Added
  `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` at the
  top of `main()` so every subcommand inherits UTF-8 stdout. Also
  replaced the arrows in that single note with ASCII `->` for

  price + `scipy.optimize.brentq` IV inversion + `call_put_mid_iv`
  (per `SPEC.iv_quote_basis = "call_put_mid"`). The inversion is a
  pure math primitive: out-of-no-arbitrage-band prices return `NaN`,
  not exceptions, so downstream sample construction can count drops
  in a `iv_inversion_failures.parquet` side-file (same pattern as
  Q1's coverage failures).
- Wrote `tests/test_iv_surface.py` with 45 cases: 30 round-trip
  parameterizations (5 sigma x 3 moneyness x 2 option_type), put-call
  IV equality at same sigma, `call_put_mid_iv` averaging + NaN
  propagation, arbitrage rejection (sub-intrinsic call, supra-S
  call, supra-discounted-K put), `T <= 0` degeneracy, non-finite
  price handling, BS price intrinsic/zero-vol edge cases, plus
  `time_to_expiry_years` correctness including a DST-transition case
  (Friday-to-Friday across spring-forward gives the right 6d23h
  wall-clock delta) and naive-datetime-treated-as-UTC.
- Documented two unlocked implementation choices in
  `decisions/2026-05-28_iv-day-count-and-arbitrage-handling.md`:
  ACT/365 with expiry at `SPEC.event_window_close_et` (15:30 ET) for
  `T`, and `NaN` (not raise, not clamp) for prices outside the
  no-arbitrage band. Neither choice affects the locked Spearman rank
  IC because (a) IC ranks are invariant to monotone IV scaling, and
  (b) drops are auditable.
- Drive-by fix: `src/metrics.py::sharpe_approx` was guarding against
  zero variance with `if std == 0.0`, but numpy's `std` of a constant
  array rounds to ~1e-18 rather than literally 0, so the guard missed
  and returned an astronomical Sharpe-approx (~9e16 for `[0.01]*100`).
  Switched to `std < 1e-12`. Pre-existing bug surfaced by the full
  test-suite run as part of compute_iv verification; would have
  spuriously passed Variant B's E1/E5 success criteria on any
  near-constant return stream.
